## 视频迁出方案（需维护者执行，涉及强制推送）

### 方案 A：Git LFS（保留 git 托管）

```bash
# 1. 安装并初始化
git lfs install
git lfs track "videos/*.mp4"
git add .gitattributes

# 2. 重写历史（会改写所有相关 commit，必须团队协调后 force-push）
git lfs migrate import --include="videos/*.mp4" --everything

# 3. CI 增加 git-lfs 检出
# actions/checkout 需带 lfs: true；npm 构建前执行 git lfs pull

git push --force-with-lease origin main
```

验收：`git ls-files videos | wc -l` 仍为 37；`git lfs ls-files` 全部为指针；
新 clone 自动拉取；`npm run verify:repo-size` 快照 < 100 MB。

### 方案 B：对象存储（R2 / S3 / OSS）

1. 上传 `videos/*.mp4` 到对象存储，开启 CORS（`Access-Control-Allow-Origin: *`）与 Range；
2. `data/videos.json` 的 `file` 改为绝对 URL；
3. `index.html` / `.htaccess` CSP `media-src` 增加对象存储域名；
4. `sw.js` 保持视频 Network-only（已有 M-07 分流，不要预缓存）；
5. 删除 `videos/` 中的 mp4 并提交。

验收：视频页可播放/拖动；断网时提示而非缓存 150 MB；仓库快照 < 100 MB。

## 建议

优先方案 B（对象存储）：Git LFS 仍需拉取全部历史对象，clone 成本不降；
对象存储可直接把仓库压到 90 MB 以内，并天然支持 Range 与大文件 CDN。
执行前需明确：托管商、域名、预算、以及 `videos.json` 的批量改写脚本。
