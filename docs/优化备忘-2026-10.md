## 一、优化方向与功能建议

### 1.1 优化方向（按杠杆排序）

| 方向 | 说明 |
|---|---|
| **大陆可达性** | 初始痛点 ERR_CONNECTION_RESET 尚未解决。零成本路线：jsDelivr 加速 JS/CSS/图片（`cdn.jsdelivr.net/gh/astrnox/TATAbox@…`），静态资源走 CDN、HTML 不动 |
| **CI 卫生** | 仓库改名（BioQuest→TATAbox）遗留 manifest anchor 校验本地失败；修掉后 CI 才真正全绿 |
| **题库扩充 + 元数据** | 现 201 题、`year` 全 null。录入历年联赛真题并标年份/来源 = 用户价值 + SEO 长尾（用内容替代被否决的 86 静态页方案） |
| **性能审计** | `legacy-fallback` / `legacy-probe` / `boot-mask` 历史包袱多，esbuild dead code 清理瘦身首屏 |

### 1.2 有趣的功能（基建均已有）

| 功能 | 可行性依据 |
|---|---|
| 实时答题对战（1v1/好友房） | Supabase Realtime 已接入；score-engine/IRT 现成 |
| 成果分享海报 | badge-motifs 已有 7 段火焰徽章，生成图片分享天然拉新 |

### 1.3 实用的功能

1. **试卷打印 / PDF 导出** — `exam.js` 无 print/export，最实的缺口
2. **Anki 导入导出** — 本站即 FSRS（Anki 同款算法），导出 `.apkg`/TSV 天然契合
3. **真题按年份/地区筛选** — 依赖元数据补录
4. **学习数据导出**（CSV/JSON）
5. **离线题包补全** — SW 已有 PRECACHE，核实题库数据是否入缓存

## 三、题目编号问题分析与优化建议

### 3.1 现状实测（2026-10-11）

| 体系 | 格式 | 数量 | 状态 |
|---|---|---|---|
| 真源规范（docs §2.1） | `M{模块}-{主题序号}-{8位hex}` | 101 题 | ✅ 四件套一致（真源=id-all=101） |
| 每日一练 | `DL-AN-01` 手写序号 | **100 题** | ❌ 游离：只存在于 6 个 bank 分片，不在真源 / id-all / manifest.files |
| 早期无 id 题兑底 | 前端 `hashQuestionId()` 32 位数字 hash | — | ⚠️ 依赖字面内容，改一个字 ID 即失效 |
| 设计中未落地 | `BQ-<topic>-<12位hex>` + `bioid-map.json` | 0 | ❌ 死代码（见 3.2-P2） |

### 3.2 发现的问题

- **P0 · 四件套一致性已破损**：bank 201 题 vs 真源/id-all 101 题，100 道 DL 题绕过了 R8 校验链、四源核对、manifest SHA 覆盖（manifest.files 只列 80 个 bank 分片，6 个 daily 分片不入清单）。
- **P1 · 规范文档自相矛盾**：§2.1 文字写"8 位 hex"，示例却混用 `M4-15-d6e03be35bca`（12 位）、`M1-02-30bbc833`（8 位）；实际存量全是 8 位。
- **P1 · 编号体系三套并存**：`M-`（存量）、`DL-`（每日一练）、`BQ-`（生成器/前端设计稿），没有一份文档声明谁是唯一真源。
- **P2 · 前端迁移链是死代码**：`storage.js` Issue #10 的 `migrateLocalDataToBioId()` 依赖 `window.bioIdMap`（由 `data/bioid-map.json` 加载触发），**该文件不存在** → 迁移函数永远 `return 0`，收藏/错题本/做题记录的旧数字 ID 永远无法迁到稳定 ID。
- **P2 · 序号段不稳**：`M1-01` 的序号是"库内顺序"，`DL-AN-01` 是手写序号——若日后重排序号，所有分享链接/纠错 issue/用户错题本引用全部错位。

### 3.3 优化建议（按优先级）

1. **P0 · 把 DL 题收编进真源**：100 道 DL 题迁移为 per-id 单题文件（`rebuild-bank-perid.py --from-bank`），分配规范 id，让四件套恢复 201=201=201=201；6 个 daily bank 分片纳入 `manifest.files` SHA 清单。
2. **P0 · CI 加四件套全量门禁**：verify 增加"bank 全部键 ⊆ 真源"“bank 文件数 = manifest.files 计数"断言，游离题再出现直接红。
3. **P1 · 收敛编号为单一真源**：以 docs 规范 `M{模块}-{序号}-{hex}` 为唯一对外 ID（工具链已落地），`BQ-` 方案废弃或仅作内部指纹；`DL-*` 不新增，收编后并入 `M-` 序列。
4. **P1 · 统一 hex 位数**：建议全文统一为 **12 位**（48 bit，与 `generate-bio-shards.js` 的 `contentSeq` 一致；8 位=32 bit 在万题规模碰撞概率约 0.05%，虽然当前 201 题够用但没必要留隐患）；存量 8 位 id 不重算（重算等于自造迁移），新题起用 12 位并在规范里写明"存量 8 位永久有效"。
5. **P1 · 写死"已发布 id 永不重排"纪律**：主题序号只增不改，删除题目留空号；在规范 §2.1 加一条红线。
6. **P2 · 让死掉的迁移链复活或删除**：二选一——(a) 跑生成器产出 `bioid-map.json`（覆盖早期无 id 的数字 hash 题），前端收藏/错题本自动迁移；(b) 若确认存量 101 题全部已有规范 id、线上无老 localStorage 数据，则直接删掉 `migrateLocalDataToBioId` 调用链，避免假功能。建议先 (a) 谨慎上线（幂等、可回滚），观察无异常后再删残余。

## 四、题目分享问题

### 4.1 现状与限制

- **无单题 permalink**：题目只在 SPA/JS 渲染中出现，无法链接到"某一道题"；纠错 issue 模板（question_error.yml）只能靠文字描述"专项练习 · 遗传 → 第 8 题"定位。
- **社交预览无解于纯静态**：分享链接的 OG 卡片永远是首页（社交平台爬虫不执行 JS，hash 参数无效）。
- **无分享入口**：share 相关代码只在 bounty/community 成绩场景，单题无"复制链接"。

### 4.2 方案建议

1. **单题 permalink**（成本最低、先做）：约定 `quiz.html#q=<题目id>`（或走 `app-routes.js` 的 `/q/<id>` 路由），启动时解析 → 加载该题 → 定位滚动 + 高亮。bioID 稳定性（第三部分的 P0/P1）是这一切的前提——链接要永久有效，ID 必须先收敛。
2. **每题分享按钮**：题卡右上角"复制链接"，移动端接 `navigator.share`；链接附 `?from=share` 埋点统计回流。
3. **分享海报绕过 OG 限制**：canvas 把「题干前 N 字 + 来源年份 + 站点二维码/域名」渲染成 PNG 保存分享——纯静态托管下这是唯一能带"预览内容"的路径（与 1.2 的成就海报共用一套生成器）。
4. **纠错定位升级**：issue 模板从"题号"改为"完整 id + permalink"，配合 `id-all.json` 的 `file` 字段可一键打开真源文件。
5. **真题入库后的分享页标注**：分享文案自动带 `来源：20XX 年联赛真题 / IBO CC BY-NC-SA`，合规（第二部分 §2.4）与可信度双赢。
6. **不做短链服务**：`M1-01-5516890d` 共 16 字符，直接可用；纯静态托管无服务端，短链方案（如 `/q/123` 映射）需要额外基建，收益不匹配。

1. P0 四件套收编 + CI 门禁（数据地基，其他一切依赖它）

5. 迁移链复活/删除二选一
6. 分享海报、打印 PDF、Anki 导出（体验层）
